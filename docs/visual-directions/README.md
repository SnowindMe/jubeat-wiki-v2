# jubeat 音乐魔方 WIKI v2：视觉方向稿

**共同前提**：目标用户是希望迅速查到国服曲目、谱面、定数和考据出处的 jubeat 玩家；首页的唯一任务是让用户理解本站的可追溯资料价值，并立即进入曲目库。三份原型均为独立 HTML，内含首页及曲目库首屏，遵守深色机台面板、无投影、方角、单一命中色和 4×4 核心构图单位等 §7 约束。

打开任一 HTML 即可预览。均以 `box-sizing: border-box`、流式容器、断点重排与移动曲目卡片防止页面横溢出；建议后续以 Playwright 实测 375 / 768 / 1440 的 `scrollWidth`。

---

## 方向一：信号网格（推荐用于“快速查歌”）

文件：[01-signal-grid.html](./01-signal-grid.html)

### 计划

| 面向 | 决策 |
|---|---|
| **Color** | `#071116` 深青黑底、`#0d1b21/#12262d` 两级机台面、`#d7ff38` 荧光黄绿色命中线；难度固定为青 / 琥珀 / 珊瑚红。颜色像机台面板上刚亮起的按键，而非霓虹夜店。 |
| **Type** | 系统无衬线承担中英文主体，数据标签使用系统等宽栈；Hero 以极大紧缩字距的中文断行制造“触控面板启动”感。 |
| **Layout** | 宽桌面是“主叙述 + 真实比例 4×4 面板”；统计和四分区均以拼接网格排列；曲库桌面为可扫描表，移动端转换为字段优先级明确的卡片。 |
| **Signature** | 曲目行 hover/focus 顶部出现 1px 荧光 Hit-Line；它既是可扫描表的当前行指针，也直接对应 jubeat 的命中时机。 |

### 自我批判

- 优点：结构最直接地承接“资料优先”，表格与来源徽标有充分视觉位置，首页/曲库的过渡也自然。
- 风险：荧光绿有轻微“技术产品”既视感；冻结时应严控为唯一命中色，不能继续加亮色装饰。
- 建议：若主人优先要可用性、曲库密度与长期维护，选此方向。

## 方向二：档案控制台（推荐用于“资料馆感”）

文件：[02-archive-console.html](./02-archive-console.html)

### 计划

| 面向 | 决策 |
|---|---|
| **Color** | `#101015` 墨紫黑、`#19191f/#24242c` 档案盒面板、`#ff7a36` 烧橙命中色；难度保留青 / 金 / 洋红。比常见深青更接近旧机台的维护控制台与归档标签。 |
| **Type** | 全站以系统等宽字体为主，曲目 ID、批次和来源天然成为版面材料；曲名仍以系统 fallback 保持汉字可读。 |
| **Layout** | 桌面左侧常驻“编号索引”，内容区像可操作的档案终端；首页更新用四格队列，曲目库不用传统表格，改为等高的紧密索引卡。移动端侧栏折为水平分区导航。 |
| **Signature** | “ID / 曲名 / 三级谱面值”的档案卡与左侧顺序索引形成双重检索坐标，让资料站一眼不同于普通游戏百科。 |

### 自我批判

- 优点：最有资料站身份，字段来源、版本号和构建日期会显得合理而非装饰；卡片格适合无曲绘的几何占位。
- 风险：等宽字大量使用会降低中文长文的亲和性；正式实现的详情考据正文须切回无衬线正文栈。
- 建议：若主人希望“严谨档案 / 考据站”成为第一印象，选此方向。

## 方向三：节奏账本（推荐用于“新人可读性”）

文件：[03-rhythm-ledger.html](./03-rhythm-ledger.html)

### 计划

| 面向 | 决策 |
|---|---|
| **Color** | `#080d18` 蓝黑底、`#111a2b/#17243a` 蓝钢面板、`#9e7cff` 低饱和紫色命中色；难度为冰蓝 / 暖金 / 玫红。紫色传达节奏轨迹而不借用常见酸绿。 |
| **Type** | 人文一点的系统无衬线为主体，宽松行高优先照顾术语、规则和考据阅读；小号数字保持清晰。 |
| **Layout** | 首页是左右对分的编辑性封面，统计条和“现在查什么”并列；曲库采用两列账本卡，单卡内有难度三段短条与来源摘要。移动端退化成单列，触控目标保持充裕。 |
| **Signature** | 曲目卡的三段难度“节奏条”不是装饰：以同一水平标尺辅助扫视 BSC/ADV/EXT 的相对等级，并复用难度固定色。 |

### 自我批判

- 优点：三者中最友好、最适合从首页导向新手与资料页；曲绘缺失时，几何格纹仍能保持节奏。
- 风险：曲库卡片的信息密度低于方向一；完整 500 首在桌面上会拉长页面，需要实现期配合虚拟化/分页增强但仍输出完整静态内容。
- 建议：若主人希望 WIKI 不显得冰冷、并把“如何读本站”作为增长入口，选此方向。

---

## 差异核对

| 维度 | 信号网格 | 档案控制台 | 节奏账本 |
|---|---|---|---|
| 首页布局 | 宽 Hero + 网格分区 | 左索引 + 内容终端 | 编辑性双栏封面 |
| 命中色 | 荧光黄绿 | 烧橙 | 节奏紫 |
| 曲库密度 | 高：表格 / 移动卡 | 中高：三列索引卡 | 中：双列账本卡 |
| 卡片形态 | 细缝表格行 | 等高档案块 | 带难度条的横向账本卡 |
| 最强性格 | 命中、速度 | 归档、追溯 | 节奏、可读 |

**待选择，不冻结。** 选定方向后，才应由 t5 把对应 CSS token、字号比例、组件状态和无障碍细则冻结为设计系统；不要把三稿混搭，否则签名元素会失焦。
